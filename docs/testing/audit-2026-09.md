# GUI audit, September 2026

Scope: every dialog and flow of the yad backend, the wrapper that starts it, and the completion
feedback of each flow. Method: the code was read, then every `ui_*` wrapper and every flow was run
against **real yad 15.0 (GTK 3.24)** on a private X server with a window manager, driven with
xdotool keystrokes and mouse clicks, with a screenshot of each dialog. Environment: Arch Linux,
bash 5.3, yad 15.0. Nothing was run on yad 0.42, on Wayland natively, or on other desktops.

## Findings

| # | Severity | Finding | Fix | Regression test |
| --- | --- | --- | --- | --- |
| 1 | High | **Message, question and error dialogs never appeared.** yad 15 has no `--info`, `--question` or `--error`; it exits "Unknown option" and the wrapper discarded its stderr. So the success and completion dialogs were missing, every fatal error under the GUI showed nothing, and every yes/no question was silently answered **No** (the DLL question always fell through to manual entry, "Retry?" never retried). | Plain dialogs with an icon and buttons, accepted by every yad. yad's stderr now goes to the debug log. | `ui_suite`: a fake `yad` that rejects the removed kinds like the real one; `smoke_yad.sh` |
| 2 | High (usability) | **The action list could return the wrong answer.** It was a radio list: clicking the "Uninstall" row highlighted it but left the radio on "Install", so OK started an install. | Single-choice lists answer with the highlighted row; the default is listed first. | `ui_suite`, `smoke_yad.sh: action_list_follows_the_highlighted_row` |
| 3 | Medium | **Game and pack names with `<` or `>` were corrupted** on bash 5.2 and newer (`<` became `<lt;`) because an unquoted `&` in a replacement means "the matched text". Corrupt markup made yad show another row's text. | Quoted replacements. | `ui_suite`: escaping on both settings of `patsub_replacement` |
| 4 | Medium | **Uninstall and update-all ended silently** for GUI users: their result was only printed to a terminal that a desktop launch does not have. | Completion dialogs on the yad backend that name the folder or the counts (whiptail and dialog already show the terminal summary). | `gui_flow_suite` |
| 5 | Medium | **Starting from the menu without yad did nothing visible.** The wrapper printed a warning to a terminal that does not exist. | The wrapper opens a terminal emulator (with each one's own run syntax, waiting for it, keeping the window open); otherwise sends a desktop notification. | `gui_flow_suite` with fake terminals |
| 6 | Medium | `ui_menu` aborted for any caller running under `set -e` (`(( _toggle = !_toggle ))` returns 1). | Plain arithmetic assignment. | `ui_suite` |
| 7 | Low | Once dialogs worked, Enter on a question answered **No** (yad focuses its first button), unlike whiptail. | Yes is listed first. | `ui_suite`, `smoke_yad.sh` |
| 8 | Low | `ui_menu` showed a raw "Key" column. | Hidden. | `ui_suite` |

## Verified on real yad

Each of these was seen working after the fixes, and the ones marked in `smoke_yad.sh` are re-checked
by it:

- Message box (icon, line breaks from `\n`, `&`/`<` shown literally, OK), question (Enter = Yes, Tab+Enter =
  No, Escape = No), error dialog (red icon, Close), entry (default selected, typed text returned, Escape
  cancels), folder chooser (selected folder returned), menu, radio-style list, check list, progress with a
  changing step text, list with hidden key column and three visible columns.
- Whole flows: install with every default; cancel at the first dialog and at the game picker; a game named
  `Tom & Jerry <Demo>`; "No" at the DLL question, an unsupported name, then a valid one; every pack
  un-ticked; a pack that cannot be cloned with retry; uninstall; update-all; a fatal error dialog; the
  missing-`7z` error dialog with real dependency detection.
- The full 69-pack shader picker: about 800x530 pixels, scrolls, labels readable.

## Review of the changes themselves

A second pass over every change of the day, before anything was committed, found and fixed:
a symlinked `ReShade.ini` replaced by a copy (`sed -i` without `--follow-symlinks`, in the released
1.3.3); a crash under `set -u` for a pack name the registry does not know; every yad dialog failing to
open when `mktemp` fails; completion dialogs that would have blocked scripted terminal runs; the terminal
fallback re-running the installer in a second emulator after a cancel; `--lab` accepting a directory full
of someone else's files, which `--purge` would then delete; a relative `--lab`; an empty merge ending the
compile check with a misleading message; an EXIT trap that reported a failed smoke run as a pass and
deleted its workspace; and a `pkill` that would have hit the user's own yad windows. Running the fixed
tooling for real then found three more: the smoke driver taking a short-lived progress window (titled like the
dialogs around it) for the next dialog, an intermittent failure; `smoke_finish` dumping binary logs into a
failure report; and xterm returning 0 whatever its command did, so the wrapper reported failed installs as
successful. Each has a test that failed before the fix.

## Not verified, or known gaps

Not fixed, and worth deciding on:

- **yad 0.42** (Ubuntu 22.04 and 24.04) was not available. The new dialogs use only long-standing options
  (`--button`, `--image`, `--no-markup`, `--hide-column`, `--print-column`), but that is unconfirmed; the
  `gui-smoke` CI job runs `smoke_yad.sh` there.
- **Native Wayland windows, HiDPI, dark themes, multiple monitors** and desktop environments other than the
  bare window manager used here. See [dialog-behaviour.md](dialog-behaviour.md).
- **Clipboard copy** of the launch option (needs `wl-copy`, `xclip` or `xsel`), the **manual folder chooser**
  driven by keyboard only, and closing the progress window mid-operation.
- **Real terminal emulators** for the wrapper's fallback: only xterm was tried for real, on a virtual display. The other
  emulators' run and wait flags come from their documentation.
- The **AppImage itself** was not launched from a desktop menu.
- Dynamic text in yad dialogs goes through yad's escape expansion, so a game path containing a literal `\n` or `\t`
  would render as a line break or tab. Vanishingly rare on Linux, and not handled.
- Warnings ("Path does not exist", "not a supported DLL override") use the information icon; a warning icon
  would say it better. Cosmetic.
- The shader picker has no "select all / none". Convenient with 69 packs.
- Colour codes are always written to the terminal; `NO_COLOR` is not honoured.
- The progress dialog puts the step text inside the bar, small, under a large label that keeps naming the
  operation. It is readable, but the step text is easy to miss.

## Reproducing

```bash
sudo pacman -S yad xorg-server-xvfb xdotool openbox    # or: apt install yad xvfb xdotool openbox
SMOKE_YAD_SHOTS=/tmp/yad-shots bash scripts/diagnostics/smoke_yad.sh
```

The screenshots in `/tmp/yad-shots` show every dialog exactly as the test saw it.
